# Fraud Rule Engine

A Spring Boot-based Fraud Detection and Case Management system that evaluates incoming insurance fraud events, applies fraud detection rules, generates alerts, creates investigation cases, and supports funds-hold workflows for high-risk transactions.

## Overview

The Fraud Rule Engine processes insurance-related events and evaluates them against configurable fraud detection rules. When fraud indicators are detected, the system:

1. Evaluates incoming fraud events.
2. Triggers fraud rules.
3. Generates fraud alerts.
4. Creates investigation cases.
5. Stores data in MySQL.
6. Supports future integration with funds hold and case management processes.

---

## Features

### Fraud Event Processing
- Accepts fraud event submissions through REST APIs.
- Persists event data in MySQL.

### Rule Engine
- Evaluates events against fraud detection rules.
- Supports extensible rule-based fraud detection.

### Fraud Alerts
- Automatically generates alerts when fraud is detected.
- Classifies alerts by risk level.

### Fraud Cases
- Automatically creates investigation cases from alerts.
- Supports investigator assignment and lifecycle management.

### Database Migrations
- Flyway-managed schema migrations.
- Version-controlled database changes.

### API Documentation
- Swagger/OpenAPI integration.
- Interactive API testing.

## Setup Instructions

### Prerequisites

- Java 21+
- Maven 3.9+
- Docker Desktop
- IntelliJ IDEA

---

### Clone the Repository

```bash
git clone https://github.com/claudellefrancis/fraud-rule-engine1.git
cd fraud-rule-engine1
```

---

### Start MySQL using Docker
Before running the command below, ensure Docker Desktop is installed and running:

```bash
docker compose up -d
```
You should see a running MySql container named"


_fraud-mysql_


Verify that the container is running:

```bash
docker ps
```

Stop the container:

```bash
docker compose down
```

---

### Configure Database

Add the below in the application.yml file:

```yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:13306/frauddb
    username: frauduser
    password: fraudpassword
```

---

### Run Database Migrations

Flyway migrations execute automatically during application startup.

Migration files are located in:

```text
src/main/resources/db/migration
```

---

### Build the Project

```bash
mvn clean install
```

---

### Run the Application

```bash
mvn spring-boot:run
```

Application starts on:

```text
http://localhost:8080
```

## Sample Fraud Event Request
Copy the below sample and paste on Swagger under the POST /api/fraud/evaluate section.
Click on "Try it out" and click on "Execute" to trigger the fraud rule.

```json
{
  "eventId": "11111111-1111-1111-1111-111111111111",
  "customerId": "CUST001",
  "policyNumber": "POL001",
  "amount": 0,
  "claimAmount": 75000,
  "eventDate": "2026-11-02T23:57:24.644Z",
  "phoneNumber": "0821234567",
  "beneficiaryAccount": "ACC123",
  "policyStartDate": "2026-10-20",
  "claimDate": "2026-11-02",
  "payoutReceived": true,
  "beneficiaryChanged": true,
  "beneficiaryChangeDate": "2026-10-24"
}
```
Mock requests used for testing Fraud Rule Engine endpoints.

high-risk-claim.json
- Large claim amount
- Beneficiary recently changed
- Expected: HIGH risk alert

repeat-phone-number.json
- Reused phone number
- Expected: Fraud rule triggered

beneficiary-change.json
- Beneficiary changed shortly before claim
- Expected: Fraud rule triggered

low-risk-claim.json
- Normal claim
- Expected: No fraud alert
